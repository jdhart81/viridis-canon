# Canonical historical provenance for enforcement activation

Immutable historical receipts can contain paths from an earlier tree, relative
sealed-input paths, or a precondition that names a mutable ledger. Their bytes
remain unchanged. The optional `historical_provenance` proof maps only the exact
reviewed original literal and SHA-256 to byte-identical canonical evidence.

Each mapping also binds its containing document and JSON pointer. A closed,
hash-pinned policy permits these exact locations; unknown mappings, changed
bytes, symlinks, traversal, missing evidence, unused mappings or altered source
pointers HOLD. External literals are never opened. All referenced children are
still checked recursively. The archived predecessor cannot replace current
registration authority: the preserving consumer independently validates the
current 27 registrations, claim bindings and public UNCERTIFIED readbacks.

The original PR #50 merge and checks remain mandatory. Installing a gate-only
successor requires its own merged PR, every original required check, successful
Actions runs for that exact head, Git ancestry and a complete closed file diff.
The new manifest contains the same 22 targets; only `nightly_coverage.py` changes.
Every other installed module, including the approved issuer intake, stays exact.
Seven generated bytecode artifacts remain private and are excluded from Git.

Actual install, post-install protected hashes, source/mirror observation,
scheduler readback, activation time and SSOT pointer must complete their own
round trip. Historical checkpoints earn no credit. Only genuine, closed future
America/New_York 01:00 windows can contribute to the seven-night streak.

This proof is activation bookkeeping. It changes no Comparator, kernel, axiom,
certificate, verifier or issuer acceptance rule, and creates no certified claim.
