# Scoped releases and the nightly staging queue

Phase 7 stages mathematical statements already covered by the designated
Comparator certificate. It preserves the original manuscript and labels its
entire historical remainder UNCERTIFIED. It does not run Lean, create a proof,
issue a certificate, or publish to Zenodo.

`science_release_queue.py --scan-certified-since Run-188 --stage` visits every
new ordinary certified run, including a delayed certificate on an older queued
run. The canonical tree and a fresh canonical corpus ledger are required. Its
immutable queue entry binds the existing certificate, receipt, sealed inputs,
mirrored source, source disposition, ledger and unchanged proof consumers.
`science_release_stage.py` uses the same builder as the catch-up packet: exact
statement/context listings, original prose archive, whole-paper byte map,
triviality exclusions, fresh INV-9 declaration proposal, per-theorem witness
review matrix, PDF and exact upload inventory. Only Tectonic may render PDFs.
Renderer failures are immutable HOLD attempts. A repeat may reuse an attempt
only when the target run's current semantic ledger row, actual source/mirror
parity, certificate inputs, consumers and closed output inventory match. An
unrelated preserving ledger refresh writes a separate revalidation receipt;
it never rewrites the frozen package. The renderer is the fixed installed
`/opt/homebrew/bin/tectonic`, not a same-named arbitrary executable.

All Methods Notes enter one weekly Viridis Methods Digest, one DOI per week.
The certificate issuance week is provenance; publication week is assigned by
the reviewed digest assembly. A review compilation containing held notes is
not a publishable digest. Each published note requires its own certificate,
exact scope, binding and final upload hashes inside the digest. Existing DOI
chains remain provenance. Standalone publication needs a Justin override.

## Independent review and publish-time binding

`scoped_release.py` consumes existing proof acceptance; it cannot provide it.
Its draft check compares the exact theorem signatures, ambient namespace and
variable context, hypotheses, conclusion, displayed source, raw statement and
candidate, certificate, model-fidelity tags, triviality and INV-9 classification.
It refuses an unassigned or mismatched per-theorem nonvacuity witness. A
certificate-listed run-level witness alone does not establish compatibility
with every theorem. Review must state the substitution or argument for each.

A `SCOPED_RELEASE_REVIEW.json` must be the actual independent Claude review,
registered by its exact hash in the SSOT approval list. It binds the current
TeX/PDF, scope map, inventory, basis, complete historical coverage and scope
diff. The receipt may resolve draft witness assignments and an explicitly
UNCERTIFIED historical projection, but cannot weaken the full frozen Lean
context or erase an underdeclared product premise.

Only then may a publish-time `PUBLICATION_BINDING.json` of standard
`VRS-SCOPED-PUBLICATION-BINDING-1` bind those exact inputs and the complete
upload inventory. A supplied dictionary or boolean is not evidence.
`publication_gate` remains fail-closed and requires the SSOT approval and fresh
consumer revalidation. Its ordinary historical status-only path is preserved.
Certification without publication is not manuscript acceptance. The public
claim map, statement inventory and foundation declaration are mandatory
hash-bound uploads. Final metadata is also a reviewed, bound input. The
metadata proposal helper produces a closed description listing only the
exact theorem names, scope disclaimer and foundation basis; broader historical
text is escaped and explicitly UNCERTIFIED. PASS requires that canonical
description already be present in the exact reviewed metadata bytes and
preserves it without rewriting. A public abstract, if present, must match it.

## Deployment boundary

The new report-only staging modules may be installed after this PR's checks
pass. The three changed existing publication consumers are prepared as a
versioned 22-target production snapshot, not silently installed. Their later
runtime deployment requires an approved release review and a fresh protected
hash closure preserving the actual installed closeout guard. The historical
snapshot must not be used to revert that newer guard. No verifier, issuer,
aligner, key, backend configuration or pinned toolchain is changed.

Portable tests use clearly labeled synthetic receipts/PDFs and injected
inspectors; these fixtures cannot supply production acceptance. Material AI
assistance: Codex implementation and test drafting under Justin Hart's Phase 7
authority. Claude's independent release audit remains pending.
