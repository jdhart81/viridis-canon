# Inactive W42 continuation source

This additive proposal has **not been activated or installed in Core**. Every
apply reaches `root_scope.require_mutation_authority`, which unconditionally
raises `HOLD_QUALIFIED_CORE_HOST_HOOK_NOT_INSTALLED`. No JSON writer/host flag,
file descriptor, ENGINE lease or Root technical scope can replace the missing
installed whole-session Core host protection. Activation requires a separately
reviewed host-integration source change and the owner's normal review, CI and
installation gates. The owning Root's existing W42 publisher route is unchanged.

The fixed proposed caller runs the current reviewed W42 outer guard, never the
quarantined successor publisher. A terminal JSON flag cannot establish SourceSession
exit. Only a child actually started by this caller, reaped with exit zero, followed
by unchanged fixed guard/config/profile/nomination/20+1/frozen130 source frames can
produce its exit checkpoint. The checkpoint is immutable and precedes Canon or
metadata work. A terminal without an owned checkpoint, a nonzero/uncertain child,
source drift or a prior started invocation holds without publisher reentry.
Retries after checkpointed publication reuse that exact evidence. Missing exact
Canon package/Root scope/scheduled review remains a downstream HOLD, not a reason
to publish another Zenodo record.

`root_scope.load(..., require_canon=True)` is deliberately W42 bounded: it consumes
the actual labelled Methods Digest terminal and registrar 3 shapes. Legacy helper
format recognition does **not** mean a successor-wave publisher has a qualified
source-exit caller here. Scheduled Claude review is mandatory for every generated
PR; `data_pr_review_policy.required` must be true. Root technical scope records
technical review under the existing provider-bound publication authority; it does
not manufacture a new Justin instruction, human exact-head approval or certification.

After actual publication, a new immutable Root scope binds
`canon_payload_manifest: {path, sha256}` and the matching exact package/source/head
hashes. The caller builds the deterministic route from that scope and fixed
adapter source. The scope does not contain a route hash that would refer back to
its own hash. The initial publication scope and genuine exit checkpoint remain
unchanged when the later technical package is prepared.

The current public Canon Methods Digest pointer schema requires a nonnull note
certificate with `LISTED_NOTE_SCOPE_ONLY`; generic publication joins also require
a nonnull certificate. Those old consumers cannot truthfully represent the new
W42 artefacts. This source therefore supports only the explicitly chosen
`public_projection_format: EXISTING_SOURCE_RECORD_WITH_RESTRICTIVE_COVERAGE`:

- Each actual W42 Run is mapped exactly once, using an admitted `.lean` note upload
  and the actual parent digest DOI. Root explicitly chooses each public path/ID.
- These are **generic source records**, not adopted Methods Digest/paper-access
  joins. Existing join tables remain unchanged. Unsupported paper-join formats
  hold with `HOLD_CANON_FORMAT_SUCCESSOR_REQUIRED`.
- New rows stay `working`, `not-canon-admitted`, outside spine/verified tags.
  `metadata.verification_coverage` stays `HOLD`, with both eligibility flags false
  and the exact approved artifact label. This uses the current consumer's
  supported restrictive coverage object, not new top-level metadata fields.
- `coverage.current_artifact` is exactly `{status: UNCERTIFIED, certifies: false,
  certificate_valid: false, certificate: null, certificate_sha256: null,
  artifact_label: <exact W42 label>}`.
- `coverage.statement_certificate_evidence` equals an explicit Root-reviewed
  child mapping with `scope`, `certifies_current_artifact: false`,
  `certificate_valid: true`, `source_evidence_sha256`, `statement_scope`,
  `scientific_predecessor_sha256`, and three public `{path, sha256}` bindings named
  `certificate`, `candidate`, `formal_statement`. Each public file target must be
  explicitly present in the approved Git payload and retain the actual private
  intake source hash. Raw private terminal/registration objects and Core paths
  are never copied into public metadata.

`descriptive_os` writes only a new private descriptive index after the exact
Canon closure. It retains current-artifact false/null certification fields and
separately scoped predecessor evidence. Its named reader verifies the exact
written bytes. It does not invoke or change the existing OS queue, install a
runtime module or admit executable science. The legacy consumer status remains
`HOLD_UNCERTIFIED_ARTIFACT`, even when the new descriptive index and both public
website metadata views have been verified.

The focused source-shaped fixture uses 151 inert local source files and distinct
original CLI versus canonical output CONFIG paths. It replaces only the real
guard/weekend hash constants for those inert bytes, and separately asserts that
production constants retain the actual reviewed pins. No Core source is imported,
no real publisher is invoked, and no public transaction occurs in the tests.
The additional default-chain fixture runs the actual caller, scope, intake,
route generator, continuation, Canon adapter, dispatcher and descriptive reader;
only the inactive host interlock and external child/Git/HTTP/SSH transports are
inert test substitutes. It also exercises metadata failure followed by recovery
with one child invocation and one Canon transaction.
