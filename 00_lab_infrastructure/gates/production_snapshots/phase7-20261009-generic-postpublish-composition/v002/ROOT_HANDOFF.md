This is an ordinary source-only invocation adapter. It supplies no scientific
acceptance rule, certificate, Zenodo mutation or cached admission. It has not
been run against a published successor and proves no publication/registration.
The prior frozen runtime/source/adoption packet stays unchanged.

## Source approval/adoption

Add `postpublish_digest.py` to an ordinary source PR, run exact-head checks,
review and merge. Prove its exact current bytes against that merge's complete
tree; copy them into a new durable source directory or execute the exact reviewed
TMP file. Root can compile the source as an explicitly bound, anonymous caller
(as the frozen root coordinator does), not install it into the runtime namespace.
No change to the frozen runtime99 closure or verification acceptance is needed.
The function itself checks its current binding and Git blob on every call.

The registered publication's PLAN keeps its authentic original merge/purpose
provenance. The new composition config names the actual merge that includes this
new adapter. These are separate source roles; do not replace historical PLAN
bindings to pretend the later source executed publication.

## Preserving SSOT closeout after actual publication

Only after the genuine weekly executor reports `PUBLISHED_STRICT_READBACK_PASS`:

1. Build a config with exactly `CONFIG_FIELDS`, `standard=STANDARD`, and the
   canonical tree root. `plan` and `publication_result` are canonical path/hash
   bindings to the actual successor PLAN and actual final RESULT. Set
   `expected_ssot_sha256` to the live ledger bytes immediately before closeout.
   `invoker` is the exact current adapter path/hash; `git_path` is its real path
   in the actual new merge. `merged_pr`, `merged_commit`, `merged_tree` bind real
   canonical evidence for that merge, including exact-head check readbacks.
2. Root explicitly calls `register_once(config, new_dated_output)` once.
   It uses the genuine PLAN's unchanged `invoke_weekly_digest.session`, source
   origin and current runtime, validates the terminal owned checkpoint, and
   consumes the boundary's actual registration receipt using the active default
   registrar. It captures the original registrar's own material inputs, obtains
   exact per-note rows, runs the real complete preserving scan, then makes one
   hash CAS through `corpus.write_guarded_ledger`.
3. It reads back the ledger, re-runs the complete real preserving scan and
   default registrar, leaves the genuine source-session context cleanly, then
   reconsumes current b52 closure/full population. `RESULT.json` is emitted only
   after those checks. No clean nights or scientific certificates are credited.
   If a post-CAS check fails, BEFORE/AFTER bytes remain as partial evidence; no
   success RESULT is emitted and root must record a truthful HOLD.

The source obtains the certificate/binding/nonvacuity/triviality/foundation
checks from the unchanged default consumers. Passing row/count comparisons do
not substitute for those checks. Original current rows and enforcement controls
must be type-exact through the CAS and final scan.

roles but update `expected_ssot_sha256` to the real registered ledger readback.
Call `prepare_catalog(config, actual_merged_checkout, new_TMP_output)`.

merge and calls `scripts.methods_digest_index.registered_digest_pointers` twice

the default registrar. Before any pointer/renderer import, the plan-selected
context calls the unchanged `live.require_origin` and `engine.require_plan`;
forged origins and malformed plans fail before output. It preserves all existing record/publication metadata,
all unknown non-digest fields, the existing digest prefix and earlier provenance.
It appends the actual current SSOT provenance for the new cohort. Output is a
proposal explicitly requiring rebuild/deployment, not publication clearance.

mistaking these historical baseline bindings for unchanged code pins.
