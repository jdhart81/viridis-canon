# Digest installation scope

The current installer accepts the fixed eighteen-module digest source table
under `VRS-DIGEST-ONLY-PDF-PACKAGING-PROFILE-1`. Its sole default route is
`invoke_digest_v2.py`. This is a separate closed schema, not permission to
omit arbitrary modules from the historical nineteen-module profile.

`publish_successor_wave_guarded.py` is excluded. Its presence as a current
source, cache, package, extension or symlink stops admission. The outer guard,
runtime validator, and both cold worker bootstraps require the same fixed
eighteen-module table at the unversioned installation path. All existing
science, source-origin, independent-review, authority, PDF, own-record,
protected-field and transaction checks remain in the digest path.

Historical v001-v006 source tables still require seventeen modules;
v007-v011 still require nineteen. Their source files, profiles, receipts and
the original 99/130 closure manifests remain unchanged. In particular, the
old dated publisher and lockstep files stay at the physical paths recorded
by those immutable closures. They serve as historical source evidence and
must not be replaced or used to dispatch a new publication.

An active dated or lockstep deployment requires a separately reviewed,
hash-bound fixed active path and an explicit entrypoint update. This digest
profile does not install or activate those routes and does not authorize
successor publication. A transport-only installation of the independently
cleared dated source is a distinct receipt-bound operation; calling its
request function does not admit its publisher entrypoint.

Tests distinguish isolated source-scope fixtures from production admission.
Passing those fixtures does not establish a live scientific pass, an
installation, a successful rehearsal, or a published release.
