# Build with Viridis Research

Viridis Research develops machine-checkable scientific and decision methods for
restoration, stewardship, intelligence, and planetary resilience. This
repository is the live, forkable source mirror for research archived on Zenodo
and for the theorem stack consumed by ViridisOS.

You do not need to begin with a new theorem. Useful contributions include:

1. reproducing a published Lean build or numerical check;
2. identifying an unstated assumption, counterexample, or scope problem;
3. contributing field data or a validation protocol;
4. proposing a reusable definition, lemma, certificate, or decision wrapper;
5. improving documentation, tests, examples, or accessibility; and
6. connecting a DOI-backed result to a reviewable ViridisOS adapter.

## Choose the right path

| Contribution | Start here | Evidence expected |
|---|---|---|
| Reproduction result | Reproduction report issue | DOI/version, environment, exact command, output |
| Field or empirical test | Field validation issue | provenance, consent/rights, units, protocol, limitations |
| New scientific idea | Research proposal issue | conjecture, assumptions, closest prior work, falsifier |
| Lean/code/docs change | Pull request | tests, provenance, license agreement, scope statement |
| Product integration | Research proposal, then pull request | DOI mapping, typed inputs/outputs, uncertainty and refusal behavior |

## What the labels mean

- **Working corpus**: public, reproducible research that has not been admitted to
  the Intelligence Bound Canon spine.
- **Series**: a thematic maturation branch for related results.
- **Canon spine**: the minimal load-bearing theorem stack. Admission requires all
  five gates in `CANON_SPINE_DOCTRINE.md` and an explicit release decision.
- **ViridisOS**: the consumer-facing decision layer. Formal proof can justify an
  algorithmic invariant, but it does not establish field validity or a real-world
  outcome.
