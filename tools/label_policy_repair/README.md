## Runtime protocol after admission

One invocation addresses one exact record and one mode (`rehearse` or `apply`).
An append-only exclusive claim per record and mode prevents crash/replay retries.
Rehearsal and publication have distinct claims and both require normal gates.
The source and every input are rechecked before every native request. A single
600-second inclusive Root bound includes startup, source/token checks, network,
cleanup and receipts. The CLI installs an independently armed kernel
SIGALRM/SIG_DFL hard end at its original 590 seconds BEFORE argparse, HTTP and JSON
imports. One fixed owned daemon thread sends a single self SIGUSR1 at original
540; the main-thread handler raises HOLD. This soft handler never replaces,
cancels or extends the kernel hard end, including during failure or cleanup.
The kernel default signal still terminates a blocking C call if the Python soft
handler is delayed. The process creates no children; it DOES own that one fixed
soft-deadline thread. No PID, signal, timer or thread function is caller selected.
Unsupported signal/nonblocking-file capabilities, non-main-thread installation,
existing signal handlers/timers or inherited blocked deadline signals refuse
before arguments, journal, credential or API admission. Hard termination leaves
claims and uncertain drafts retained; it is not cleanup confirmation. The external
Root action must still enforce and measure total <=600 seconds, including its
receipts; this source does not establish crash-surviving operator qualification.
No automatic retry is present. Any failure permanently poisons that action.
All regular input reads use no-follow/nonblocking/close-on-exec descriptors,
16MiB per-input and 65536-byte chunks, stable identity/hash and remaining-time
checks before/after each chunk. Source and admission hashing use those same
bounded reads. Network JSON retains its existing10MiB response cap, while actual
in-flight blocking calls remain covered by the independent kernel alarm.

Before creating a draft, the tool anonymously checks the native record, every
public file's exact size/SHA, absence of an existing draft, and the API revision
and ETag. It sends the full draft body with only the approved metadata projection,
checks the full readback, and requires its exact ETag before publication.
Rehearsal always discards its own draft and verifies the unchanged public record.
Publication requires an anonymous exact metadata and all-file readback. Failure
may discard only an ownership-confirmed draft and must confirm 404/410; cleanup
never clears or replaces the first failure.

Credentials are read internally only after admission from the fixed relative
Markdown path `secrets/Zenodo_API/Zenodo_token.md`, using a stable regular-file
read. The historical extraction algorithm is retained, with ambiguous longest
tokens rejected. A token is used only as the Bearer header at the fixed Zenodo
API host, never in logs, output, URL, exception text or environment. Redirects and
the legacy endpoint override environment variable are forbidden. An explicit
ProxyHandler({}) disables ambient proxy discovery and proxy credential forwarding;
no cookie processor is installed.
Every metadata record/draft request uses
`Accept: application/vnd.inveniordm.v1+json`. Anonymous binary file-content GETs
instead use `Accept: */*` and `Accept-Encoding: identity`, with the pinned exact
size/SHA path; no JSON schema is applied to binary bytes and credentials are
forbidden on file reads. A406 or any other unexpected status poisons the action
without retry. The distinction follows the retained actual read-only serializer
observation; it is not evidence that this new tool has run. A legacy
JSON metadata representation fails before mutation; there is no fallback serializer or
conversion of legacy keywords/files/revision into a native mutation body.
